Can a coding agent learn from sessions that already happened?

AGENTS.md is the instruction file a coding agent loads at the start of every session. Skill optimizers improve it by re-executing tasks after each edit and scoring them pass or fail. Real sessions happen once, and feedback is at most a short comment from the user. Hone learns from these finished sessions and comments, and it never re-executes a task.

1How Hone works

@@SVG@@

1Trace collection. Sessions arrive as traces with optional user feedback.

2Batch assembly. Unanalyzed traces form a frozen batch, fixed for the whole run.

3Review. Reviewers on different LLMs analyze the batch, and the judge cross-examines them.

4Propose. Proposers read the report and past decisions, and the judge fuses one edit set.

5Verify and commit. Anchors match once and cite the batch. If not, only propose re-runs.

A finding becomes an edit only if it repeats across sessions and holds up when the judge questions it.

2Results on two benchmarks

@@CHARTS@@

Hone scored highest on both benchmarks, 3.0 and 11.3 points above the Pi agent it started from. The two differ only in AGENTS.md.

All systems use GPT-5.4-mini. Hone saw only traces and text feedback, and it optimizes one AGENTS.md for one domain at a time.
